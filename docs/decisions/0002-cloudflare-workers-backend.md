# ADR 0002：后端采用 Cloudflare 全家桶

- 状态：已采纳
- 日期：2026-10-14

## 背景

需要一个中央协调库，负责玩家统计缓存、回放众包采集、模型分发、预测记录汇聚。核心诉求是低运维成本、低起步成本、能推迟扩容时的迁移。

## 决策

后端采用 Cloudflare 全家桶，各组件分工如下：

| 组件 | 用途 |
|---|---|
| Workers | API 网关、鉴权、限流、路由 |
| KV | 玩家统计数据缓存、模型元数据 |
| D1 | 对局索引、玩家元数据、聚合统计 |
| R2 | 原始回放、训练数据导出、模型产物 |
| Durable Objects | 按服务器聚合计数、去重协调 |
| Queues | 异步入库削峰 |

## 理由

**零运维。** 无需管理服务器、数据库实例、证书。个人项目维护成本是决定性因素。

**免费额度充足。** 早期完全免费。KV 每天十万读、D1 每天五百万行读、R2 十 GB 存储加出网免费，对早期规模绰绰有余。

**R2 出网免费。** 这点对训练数据导出特别关键。将来把几十 GB 训练集拉到本地跑模型，不产生流量费。

**全球分发。** 客户端分布在各服，边缘节点就近响应。

## 代价

**D1 单库十 GB 上限。** 逐场对局记录只增不减，是增长主力。需要架构上预留迁出路径。

**D1 按行读取计费。** 免费版每天五百万行读。不带索引的查询就是全表扫描，每行都计数。所有查询必须走索引。

**KV 写入限制。** 同一 key 每秒只能写一次，不适合存频繁更新的计数。

**Workers CPU 时间有限。** 不适合跑重计算，模型推理必须放客户端。

## 应对

数据访问全部藏在 `IBattleRepository` 接口后，见 ADR 0005。D1 触顶时切换 Neon Postgres，业务代码零改动。

云端 D1 只存可索引的查询字段，明细压缩或推 R2。逐场明细表预留迁出路径。

## 备选方案

**Neon Postgres。** 纯 Postgres，按用量计费，缩容到零，支持分支。适合时间序列增长与分析查询。评估后作为 D1 触顶后的迁移目标，而非起步选择，因为起步阶段 D1 的零成本与零运维更优。

**Supabase。** Postgres 加一整套 BaaS。附带的认证、存储、实时功能本项目用不上，等于花平台钱买闲置功能。且免费版闲置一周会暂停，对个人项目不便。

**自建服务器。** 运维成本高，个人项目不划算。
