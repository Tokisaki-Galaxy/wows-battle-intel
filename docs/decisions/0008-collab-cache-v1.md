# ADR 0008：协作缓存 v1 与上报防线

- 状态：已采纳
- 日期：2026-10-16

## 背景

客户端直连 WG API 限流紧（约 20 req/s 每应用），一局 24 名玩家每人一次查询，
同地图同服玩家重复拉同一批账号是纯浪费。建立服务端共享缓存：客户端批量查服务端，
未命中再直连 WG，回传补拉结果形成互助缓存。

服务端免费档约束：D1 每天 10 万行写、Worker 每请求 CPU 10ms 量级、KV 每天 1000 次写。
上报接口完全开放，任何人可灌脏数据（训练投毒 T1）或烧配额（经济攻击 T2）。
用户明确要求：不做账号绑定（WG OpenID 否决）、服务端计算压力最小化、
客户端强制限频、女巫攻击无收益。

## 决策

### 时隙承诺上报（防女巫与限频合一）

客户端上报前本地挖一张票据：找 nonce 使
`SHA256(device_id || secret || slot || nonce)` 前 16 bit 为 0，
其中 `slot = floor(now / 300)` 为五分钟时隙。服务端验证重算一次哈希
（微秒级）并检查 slot 属于当前或上一时隙，D1 主键 `(device_id, slot)`
天然实现同时隙同设备一次的幂等去重。

性质：

- 正常用户约 6.5 万次哈希，毫秒级无感，可后台预挖。
- 限频物理锁死：同一设备五分钟最多一次有效上报。
- 女巫无收益：一万设备与一台设备的可回传总量都被全局限额 8 万行/日封顶。
- 服务端成本与设备数解耦：验证 O(1)，D1 查询走主键。
- 放弃 VDF：.NET 无成熟实现，自研风险高。放弃 OpenID：决策人不引入账号流程。

### 回传范围锁定

批量查询未命中时签发一次性 missingToken（记录账号清单与过期时间）。
回传必须携带 token，且数据行集合必须 ⊆ token 声明范围。token 用后即废。
客户端无法借回传通道灌入未请求过的账号。

### 三级限额

设备 2000 行/日、IP 哈希 2 万行/日、全局 8 万行/日。
计数走 `rate_limits` 表每键每日一行 UPSERT，限额系统自身写配额可控。
全局上限低于 D1 免费档 10 万行/日，烧穿全局额度也不伤库。

### 数据不变量校验（六条，带拒绝码）

| 校验 | 规则 | 拒绝码 |
|---|---|---|
| 认证 | 设备存在、slot 票据哈希达标 | E_AUTH |
| 范围 | 行集合 ⊆ missingToken 声明 | E_SCOPE |
| 时隙 | slot 为当前或上一时隙且未用过 | E_SLOT |
| 范围值 | 胜率 0..1 或 -1 哨兵 | E_RANGE |
| 守恒 | wins ≤ battles；单船 battles ≤ 账号 battles | E_CONSERVATION |
| 合理性 | battles < 100 万；accountId 纯数字；server 在枚举内 | E_PLAUSIBLE / E_FORMAT |
| 时间 | captured_at 取服务端时间，客户端自报时间拒收 | E_TIME |

拒绝写 rejection_log（七天滚动清理），管理端点 `GET /api/v1/admin/rejections`
凭 ADMIN_TOKEN 查看。

### 信任分级预留

设备表与缓存表带 trust_level 列，v1 恒为 0（匿名）。
将来引入任何身份增强（OpenID、PoW 注册门槛）只改写入侧，读取与训练端
按列过滤即可，不迁移数据。

### account_id 存原值

决策人拍板。WG 账号 ID 在生态内公开可查，增量隐私风险可接受。
隐私说明写明上报内容：账号 ID、服务器、船只、比分、统计数字。

## 后果

- 客户端上报循环：query → WG 补拉 missing → 挖票 → report。
- KV 不再承载统计缓存真相（每天 1000 次写配额太紧），player_stats_cache 表
  是唯一缓存源，TTL 在读取端按 captured_at 判断（账号 7 天、单船 3 天）。
- 现有 `/api/v1/battles/upload` 与 `/api/v1/stats` PUT 保留兼容，
  后续客户端切换到新端点后评估下线。
- 模型分发不变，客户端需补 sha256 校验与 PinnedModelVersion（客户端侧待办）。
