# 领域术语

本文件定义项目内的统一语言。代码命名、文档、表结构都以这里的定义为准，避免同一概念出现多种叫法。

## 战斗 Battle

一局对战的完整记录。由游戏写出的元数据 `tempArenaInfo.json` 或回放文件的元数据段描述。包含对局类型、开始时间、参战者、友方、敌方。

来源两种：赛前从 `tempArenaInfo.json` 读到的是进行中的战斗，赛后从 `.wowsreplay` 解析出的是已完成的战斗。

## 参战者 Participant

战斗元数据里列出的一个玩家或机器人。在拉取统计之前，一个参战者只有阵营关系、服务器、船 ID、名字。

## 玩家统计 PlayerStatistics

为一个参战者归一化后的账号、单船、单人、双排、三排、经验、伤害、公会、隐藏战绩、加权胜率数据。

## 统计源 StatisticsSource

获取玩家统计的外部提供方。当前有 Vortex、WG Public、WG Public via Yuyuko proxy。

## 战斗接收 BattleIntake

完整的一次处理流程：解析战斗、解析服务器、选择统计源、拉取玩家统计、套用关注名单、计算战场、生成输出文本。

## 战场 Battlefield

一场战斗计算后的呈现形态：友方、敌方、队伍聚合、排序投影、图表输入。

## 关注名单 WatchList

按服务器划分的用户数据，把玩家标为 Positive、Negtive、Cheater 或 None。历史拼写 `Negtive` 是兼容契约，不要改。

## 舰船目录 ShipCatalog

带版本的本地元数据，把船 ID 映射到本地化名称、类型、等级。

## 输出文本 OutputText

由战场统计生成的、可配置的文本，供复制或展示。模板标签与精确格式是兼容契约。

## 回放观测 ReplayObservation

在配置的回放目录下发现新的 `.wowsreplay` 或 `tempArenaInfo.json`。观测与解析是分离的职责。

## 预测 Prediction

在战斗开始前，模型对某一方获胜概率的估计。带模型版本与预测时间戳，必须可事后追溯与校准。

## 校准 Calibration

预测概率与实际结果频率的一致性度量。用 Brier 分数与校准曲线衡量。这是本项目的核心产出指标。

## 近期状态 RecentForm

玩家在最近一个短窗口内的表现，区别于账号总胜率这种长期累积指标。窗口以场次计，默认最近 20 场。

## 会话状态 SessionState

玩家在一次连续登录游玩期间的表现与心理状态代理指标，如连续失败次数、会话内胜率、近期表现偏离。

## 服务器基线 ServerBaseline

某一服务器内玩家水平的分布基准。用于把绝对胜率转成服务器内的相对位置，使跨服数据可比。

## 组队结构 DivisionStructure

一个玩家以单人、双排还是三排参与对局，以及各组队形式下的历史表现。组队协同性是账号总胜率无法体现的额外信息。

## 中央协调库 CentralCoordinator

云端后端，负责玩家统计缓存、回放众包采集、模型分发、预测记录汇聚。起步用 Cloudflare 全家桶。

## 匿名化上报 AnonymizedUpload

本地采集端向中央库发送数据时的处理。只传账号 ID 与统计数据，原始回放默认不上传，是否上传由用户选择。

## 不变量 Invariants

- 战斗文件以兼容游戏写入或替换的方式打开。
- 按既有 ID 规则排除的机器人保持排除。
- 服务器选择与统计源回退保持现有区域行为。
- 隐藏或不可用的统计保留既有的负数哨兵语义。
- 关注名单、设置、窗口位置、截图、日志保持既有的用户数据位置。
- 软件更新永不覆盖关注名单、窗口位置、日志、截图或下载运行时数据。
- 任何预测记录都必须带模型版本，且不可事后篡改。
