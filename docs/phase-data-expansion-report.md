## 回放去重靠对局标识，不靠文件名

同一局被两名玩家各录一次时，两份回放的开局时间接近、地图与参战者集合相同，`BattleIdGenerator` 据此算出的 `battle_id` 一致。导入 1016 份解析结果后，`battles` 表主键收敛为 988 局。

文件名不可靠。文件名里的时间戳是战斗结束时写盘的时刻，两个客户端相差数秒。按文件名去重会漏掉大量同局异名的重复。

**已知局限。** 两名录制者的开局时间戳存在数秒偏差，`battle_id` 截断到秒，导致同局在时间戳跨越秒边界时算不出同一个标识。实测有 225 组参战者集合与地图相同的重复，其中 210 组时间差在 5 秒内。后续应把时间对齐到容差窗口后再哈希。

## 修复的核心问题：友敌判定依据错误

这是本阶段最重要的发现，直接决定预测是否有判别力。

### 问题现象

训练指标异常：账号胜率差的 AUC 仅 0.497，接近随机。胜率分桶非单调，`[0.49,0.51)` 桶的队伍获胜率 61.6%，与相邻桶的 46% 严重不连续。

### 根因

`ReplaysharkMapper` 用 `battle_result.team_id` 作为录制者所在队伍，进而用它判定友方。实测确认该字段是**获胜方队伍**，不是录制者队伍。

扫描 380 份回放，按胜负拆分一致率：

| 结果 | 录制者队伍与 `battle_result.team_id` | 一致率 |
|---|---|---|
| Win | 一致 221，不一致 0 | 100% |
| Loss | 一致 0，不一致 159 | 0% |

再看录制者的阵营与结果交叉：`team=0` 只在 Win 出现，`team=1` 只在 Loss 出现，651 局无一例外。这等于把「友方」定义成了「胜方」。

后果是所有失败局的友敌判定整体反转，482 局的双方特征互换。模型一半样本是反向噪声，判别力被抵消。

### 修复

录制者队伍改从 `is_self` 标记的玩家取。回放必然恰有一名录制者，其 `team_id` 即录制者所在队伍。`is_self` 在 1065 份文件中全部存在且唯一，`relation` 字段则恒为 0 不可用。

### 修复效果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 单玩家胜率 AUC | 0.5074 | 0.5520 |
| 队伍均值差 AUC | 0.4923 | 0.7503 |
| 胜率分桶 | 错乱尖峰 | 单调递增 0.386 到 0.626 |
| 逻辑回归 Brier | 0.2436 | 0.2028 |
| 逻辑回归准确率 | 57.40% | 68.05% |
| LightGBM Brier | 0.2198 | 0.1877 |
| LightGBM 准确率 | 66.27% | 73.25% |
| 加权基线 AUC | 0.4969 | 0.7505 |

## 修复：训练集混入 PvE 噪声

数据集构造时不按对局类型过滤，Coop 等 PvE 模式被纳入训练。

证据：94 局 Coop 中 91 局的敌方全是机器人，没有 WG 账号统计。特征计算时敌方平均胜率为 0，友方约 0.5，差值恒为正，模型恒预测友方获胜。而 PvE 友方实际胜率 96.8%，于是 AUC 得到 1.0000、Brier 0.0194 的虚假完美值。

这是典型的数据泄漏假象：模型学到的不是玩家水平，是「对面没有数据所以对面弱」。混入后整体 AUC 被从 0.4969 抬到 0.5791。

修复方式：`load_battles` 增加 `allowed_battle_types` 参数，默认白名单为 Random 与 Ranked，传空元组表示不过滤。新增 `skipped_battle_type` 统计项。CLI 各命令加 `--all-types` 开关便于对照。

## 修复：对局类型映射不完整

回放的 `game_type` 实际写作 `CooperativeBattle`，但映射表只认 `CoopBattle` 与 `PVEBattle`。现有数据因 `match_group` 为 `cooperative` 侥幸映射正确，但 `match_group` 缺失或变化时会误判。已补全映射表并明确 `game_type` 优先、`match_group` 兜底的分工。

Brawl 与 Event 等特殊模式没有对应枚举，稳定归 `Unknown`，会被训练白名单正确排除。

## 当前指标

修复后，用 845 局 PvP 训练：

| 模型 | Brier | 对数损失 | 准确率 |
|---|---|---|---|
| 无信息基线 | 0.2500 | 0.6931 | 53.96% |
| 加权胜率差基线 | 0.2425 | 0.6781 | 68.88% |
| 逻辑回归 | 0.2028 | 0.5937 | 68.05% |
| LightGBM | 0.1877 | 0.5592 | 73.25% |

加权基线的队伍均值差 AUC 为 0.7505，符合 XVM 类工具的应有水平。校准曲线仍偏保守，`0.4-0.5` 桶实际胜率 0.345，这与单场方差极大的客观性质一致。

## 时间泄漏仍是未解的约束

现有玩家快照全部为事后补采，时间戳晚于所有对局。默认防泄漏模式下 0 局可用，只能用 `--allow-future` 跑通管线。

账号总胜率是长期累积量，短期内基本稳定，用它近似对局当时的胜率误差可忽略，这是 XVM 与 ApeRadar 的标准做法。但近期状态与会话状态这类短期特征必须严格按时间切分，只有中央库众包按时间累积快照后才能真实评估。

因此以上指标仍偏乐观，但友敌判定修复后，判别力的方向与量级是可信的。
