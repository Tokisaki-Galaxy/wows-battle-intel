# ADR 0009：运行日志落盘并按时长与体积双限清理

- 状态：已采纳
- 日期：2026-10-17

## 背景

运行日志原本只有进程内的 500 条环形缓冲，界面能看到，进程退出即丢。出问题时最需要的是崩溃前那几条，而恰恰这时候什么也看不到。

另外日志不能无限写盘：一场对局几十条，长时间挂机后文件会持续变大。

## 决策

日志在内存缓冲之外增加一层 `ILogFileWriter` 落盘，实现是 `LogFileWriter`：

- 按本地日期滚动，文件名 `app-yyyyMMdd.log`，一行一条，格式 `yyyy-MM-dd HH:mm:ss.fff [LEVEL] 消息`。
- 写入先进内存缓冲，满 64KB 或每 5 秒刷盘一次，退出前强制刷出。
- 清理口径三个开关：只按天数、只按体积、两者同时生效。默认同时生效：先删超过保留天数的文件，再按体积从最旧删起。
- 默认落仓库根 `Logs`，发布包场景退回 `%APPDATA%\wows-battle-intel\Logs`。目录、天数、体积、口径都进配置，可在设置页修改。

## 理由

**纯文本按天切分。** 出问题时可以直接用编辑器打开，也可以用 `rg` 搜关键字，不需要额外工具链。

**缓冲刷盘而不是逐行落盘。** 日志写入可能来自界面线程，每次同步写盘会把界面拖慢。64KB 缓冲在崩溃时最多丢几秒内容，代价可接受。

**默认双限。** 只限天数时，一天写爆磁盘也没人管；只限体积时，几天不写也清不掉旧文件。两个都开着最贴合直觉。

**失败静默降级。** 写日志失败再抛异常，会把调用方的业务线程一起带崩。写入器吞掉所有 IO 异常并置为降级状态，之后只保留内存日志。

## 代价

**裁剪正在写的文件。** Windows 上追加句柄不允许另一个句柄改写同一文件，截断当前日文件前必须先换成共享读写句柄，写完再恢复追加流。这段换句柄逻辑是本实现里最容易出错的地方，已用单元测试覆盖。

**回填不复写。** 启动时把上次运行的日志读回内存缓冲，只走 `ReplaceHistory` 进内存，不写盘，否则每启动一次日志就自我复制一遍。代价是界面看到的回填条目不会被再次持久化，但它们本来就在磁盘上。

**按日期文件名判定新旧。** 清理按文件名里的日期排序，不读文件内容时间戳。这个口径简单但对系统时间回拨不敏感，时间被手动改过后可能留下顺序错乱的文件，下次清理会自然收敛。
